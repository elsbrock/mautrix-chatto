# Contributing

## Layout

| Path | What |
|---|---|
| `cmd/mautrix-chatto` | `main`, a thin bridgev2 `mxmain` wrapper |
| `pkg/connector` | The bridgev2 network connector: logins, Chatto → Matrix (`handlechatto.go`), Matrix → Chatto (`handlematrix.go`), chat info, backfill, media, ghost bots, OAuth, commands |
| `pkg/chattoclient` | Chatto client: ConnectRPC services, HTTP auth (login, refresh, logout, OAuth), realtime v4 WebSocket |
| `pkg/chattofmt` | Chatto Markdown ↔ Matrix HTML, including Chatto's mention and linkify rules |
| `pkg/emoji` | Unicode ↔ gemoji shortcodes (generated by `tools/gen-emoji.mjs`) |
| `pkg/chattoid` | ID mapping and DB metadata types |
| `pkg/bridgemetrics` | Prometheus collectors |
| `pkg/chattotest` | In-memory fake Chatto server for tests |
| `pkg/chattopb` | Generated protobuf and connect-go code (do not edit) |
| `proto/` | Vendored Chatto protos (Apache-2.0, do not edit) |
| `nix/` | Package and NixOS module |
| `deploy/monitoring` | Grafana dashboard (generated by `tools/gen-dashboard.py`) and alert rules |
| `docs/decisions` | Architecture decision records |

## Workflow

- Use the dev shell (`nix develop`) or Go ≥ 1.26 plus golangci-lint v2.
- Build with `-tags goolm` (pure-Go olm, no libolm).
- Run `scripts/check.sh` before every push: vet, lint and race tests, failing
  fast. CI also runs fuzzing, a generated-code drift check, `nix flake check`
  and `nix build`.
- Commits use [Conventional Commits](https://www.conventionalcommits.org/):
  `feat`, `fix`, `test`, `docs`, `build`, `ci`, `refactor`, `chore`, with an
  optional scope (`feat(connector): …`).
- Record non-obvious decisions as a short ADR in `docs/decisions/`.

## Tests

Everything is tested without a real Chatto server or homeserver:

- **`pkg/chattotest`** fakes Chatto. It is built on the generated connect
  handlers, so request and response shapes are the real ones. It covers HTTP
  auth with single-use refresh tokens, the realtime protocol (cursors,
  replay, snapshots, close frames, heartbeats), timelines, threads, uploads,
  bots and permissions. Hooks let tests drop connections, expire cursors or
  tokens, and publish events before RPC responses.
- **`pkg/connector/harness_test.go`** runs a real bridgev2 `Bridge` on SQLite
  with a mock Matrix connector (`matrixmock_test.go`) that records every
  event the bridge sends. Tests post on the fake Chatto and assert on Matrix
  events, or inject Matrix events with `sendMatrix` and assert on Chatto state.
- **Format converters** have table tests, Chatto's own 86 shared mention
  cases, round-trip tests and fuzz targets:
  `go test ./pkg/chattofmt -fuzz FuzzToMatrix`.

When adding a feature, add the RPC to the fake if needed and a round-trip test
in `pkg/connector`.

## Updating to a new Chatto release

```sh
scripts/sync-proto.sh v0.5.0          # bumps UpstreamVersion, re-vendors protos, regenerates
go build -tags goolm ./... && scripts/check.sh
```

Then:
- Read the upstream changelog for realtime and API changes.
- Update `docs/chatto-protocol-notes.md`.
- If `go.mod` changed, update `vendorHash` in `nix/package.nix`
  (`nix build 2>&1 | grep got:`).

## Regenerating other generated files

```sh
buf generate                  # pkg/chattopb from proto/
node tools/gen-emoji.mjs      # pkg/emoji/emoji_gen.go from gemoji
python3 tools/gen-dashboard.py
```
