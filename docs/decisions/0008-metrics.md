# 0008: Metrics and health endpoints

Status: accepted (2026-10-25)

## Context
mautrix-go v0.32 bridgev2 has no Prometheus metrics.

## Decision
- The bridge keeps its own Prometheus registry (`pkg/bridgemetrics`) with Go
  and process collectors plus:
  - RPC latency and errors by procedure and code
  - realtime connection state, reconnects by reason, recoveries by result,
    events by type and event lag
  - messages bridged and errors by direction and type
  - token refreshes by result
  - logins by bridge state
  - server and build info
- These are served on a separate listener (`network.metrics.listen`) together
  with `/healthz` (process alive) and `/readyz` (connector started). The
  appservice port is not reused, so metrics can stay on localhost.
- Grafana dashboard and alert rules live in `deploy/monitoring/`. The
  dashboard is generated by `tools/gen-dashboard.py`.
